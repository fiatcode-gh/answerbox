# Answerbox: decisions

Called go-exam until 2026-11-19. Entries dated before that keep the names of their time: the command `cmd/go-exam`, the settings `GOEXAM_*`, the database `go-exam.db`, the cookies `goexam_*`, the host `go-exam.fiatcode.dev`.

A self-hosted web app for classroom exams with multiple-choice and fill-in questions. Students type an exam code and their name; teachers sign in with Google, import exams from text files and review the results of their own exams. Built 2026-11-13 to 2026-11-15; teacher accounts added 2026-11-16; exam codes and several open exams added 2026-11-16; exam length and schedules added 2026-11-16; exam revisions, download and copy added 2026-11-17; form editor added 2026-11-17; exam archive added 2026-11-18; exam sections added 2026-11-18; fill-in questions added 2026-11-18; renamed to Answerbox 2026-11-19; UI revamp 2026-11-19 to 2026-11-20 (the "Friendly classroom" look in light and dark, Atkinson Hyperlegible Next for student-facing text, confirmation pages, a projector view, a results list that refreshes itself, attempt counts on the exam page, a public page with a Join and Resume entry card); Indonesian and English added 2026-11-20 to 2026-11-21.

## Scope

- In: Google sign-in for teachers; a teacher list managed by admins; exam ownership (each teacher sees only their own exams, admins see all); several open exams, each entered with its own code (typed, or carried by a link); exams that open and close by hand or on a one-off schedule (an open time, a close time or both); Markdown-like exam files (or a zip with images); an in-app editor for exams without attempts (new exam, edit, add, remove and move questions, options, images, settings), every save a revision with a summary written by the app; numbered revisions of exam content with a history page and a read-only view of each revision; the revision each attempt started on; download of an exam as a file; copy of an exam; archiving and unarchiving exams (archived exams leave the exams list, stay closed, keep their code and results); named sections with instructions, in the file format, the editor, the exam pages, the shuffle (inside each section) and the results (a score per section); fill-in questions with 1 to 10 accepted answers, matched ignoring letter case and extra spaces, with Indonesian numbers compared by value, and a teacher override per typed answer once the attempt has ended; a cookie-bound attempt plus a teacher-issued resume code; a per-exam length (5 to 240 minutes, default 60) enforced by the server as a wall-clock limit; shuffle and `show_result` set per exam; attempts list (sortable, filter by name), detail, teacher rename, CSV export, delete; the "Friendly classroom" look, light or dark by the device's setting, with Atkinson Hyperlegible Next for student-facing text; a projector view of an exam's address, code and link; confirmation pages before removing a question, a section or a teacher and before archiving; a results list that refreshes itself; attempt counts by status on the exam page; a public page that says what Answerbox is, with a Join and Resume entry card; every page in Indonesian or English, following the browser's language on a first visit, with a language switch on every page; a container image for the existing Traefik/Podman VPS.
- Out: student accounts, a Workspace-domain rule, password sign-in, moving an exam to another teacher, promoting admins in the app, a history of Open, Close, schedule, archive, rename or delete actions (revision history covers exam content only), restoring, deleting or comparing revisions, cleaning up images of old revisions, teacher-written revision notes, undo, drafts, a live preview in the editor, deleting uploaded images, locking between teachers (an outdated page is refused instead), per-question statistics, math rendering, regenerating or choosing an exam code, QR codes, throttling code guesses, recurring schedules, time zones per teacher or per exam, ending attempts at the close time, changing the length after attempts exist, anti-cheating beyond shuffle and the monitor below (no fullscreen, no force-submit, no live push), editing answers, deleting whole exams, archiving several exams at once, automatic archiving, recording who archived, a live dashboard, per-section time limits, shuffle settings or scores on the student's score page, section numbering by the app, nested sections, moving a whole section, a navigator grouped by section, adding a question inside a chosen section, several blanks in one question, a blank inside the sentence, partial credit, numeric tolerance or ranges, patterns or wildcards, a case-sensitive or exact-match switch, units (`5 cm` = `5cm`), overriding multiple-choice answers, override history or comments, telling the student about an override, overriding an unanswered question or an attempt in progress, typed answers in the CSV, a number keyboard on phones, a theme switch, script dialogs, live push for results, web fonts from another site, other interface languages, a default-language setting (per installation or per teacher), translating exam content, a language choice stored on the server. Deployment wiring (quadlet, Traefik route, backup and drill scripts, Gatus, Diun, DNS) belongs to a separate `fiatcode-infra` unit.

## Decisions and why

- **Go, server-rendered, one SQLite connection.** The VPS has 3.8 GiB and no swap. One `*sql.DB` with `MaxOpenConns(1)` and `_txlock=immediate` makes every write serial, so races (start vs replace, start vs close, resume swap) are closed by transactions instead of locks. Measured: 100 students, 4000 saves, p95 about 55 ms, about 20 MB of memory.
- **Invariants live in the schema too.** Exam codes are unique, well formed, required and fixed in the schema (a unique index, a check and two triggers), and triggers freeze questions and options once an attempt exists. A future code path that forgets the service check still cannot change an answer key after scoring started.
- **Nothing derived is stored.** The score is counted from answers, and the shuffle order is recomputed from a per-attempt seed. That leaves no stale copies to keep in sync.
- **Deadline:** the exam's length from start plus a 3 s grace for network delay, invisible to the student, fixed when the attempt starts. One sweep statement finalises overdue attempts; it runs at the start of every attempt transaction and every 5 s in the background, so abandoned attempts become `timed out` with no browser connected. Submit at or after the deadline records `timed out`.
- **Answer-key isolation by type.** Student view types have no correctness field. Tests compare full responses from two apps with different keys, byte for byte.
- **Resume codes** (8 characters, no ambiguous letters) always exist for unfinished attempts. Redeeming one swaps the cookie token and issues a new code in one transaction, so the old device loses access.
- **Images** go through one `os.Root`, under a random per-import key with content-hash names. Zip entry names never reach a filesystem call, and image types are checked by content sniffing (PNG, JPEG, GIF, WebP; no SVG).
- **Admin requests** get a fresh 15 s database budget after the upload body is read. Upload time is bounded by the 60 s `ReadTimeout` instead (about 1.4 Mbit/s for 10 MiB).
- **Countdown on a monotonic clock** (`performance.now()`), re-anchored on every server response, so moving the device clock cannot trigger an early submit.
- **Anti-cheat monitor** (added 2026-11-16, amends "anti-cheating beyond shuffle"): a per-exam `monitor: on | off` header, default on; migration 0002 adds `exam.monitor` (existing exams on) and an `attempt_event` table. The exam page blocks copy, cut, paste and the context menu and reports them, plus leaving the page for more than 3 s (counted once per absence) and resizes (width only on touch devices); the student sees "Your teacher has been notified." for 5 s after each event. The banner hangs under the sticky bar and overlays the page, so showing or hiding it moves no question; once the bar is stuck at the top of the window, jump targets and the navigator move below it while it shows. Events have their own queue in the page with a single backed-off retry, separate from answer saves, and carry the server's time and the question's file position: for copy, cut, paste and right-click the question that contains the pressed or selected element, otherwise (and always for leaving the page and resizing) the first question still visible below the bar. The monitor starts after the countdown, inside `try/catch`, so it cannot stop timing or saving; the banner lookups run inside it too, so a page without the banner loses only the monitor. The server stores events only for the cookie's in-progress attempt with the monitor on, at most 500 per attempt, and never reads them for score or timing. A screen wake lock, when the browser grants one, avoids false flags from a sleeping screen. It detects and discourages; it cannot see other apps, devices, screenshots or extensions, and a student can still disable JavaScript-side reporting.
- **Flags show the student's number** (2026-11-16, after the first real exam). With a shuffled exam the stored file position was not the number the student saw. The attempt page now shows "Question 3 on screen (file question 7)"; the screen number is recomputed from the attempt's seed and the exam's shuffle mode through the same layout as the student's page, so nothing derived is stored and no migration is needed. An unshuffled exam shows one number.
- **Teacher pages show clock times without seconds** (2026-11-16). The nine-column attempts table did not fit the 1100 px page column of that time and "Delete" was cut off. The table shows `HH:MM` with the full date and time in a tooltip; one date line sits above it when every shown attempt started on the same date in the configured zone, otherwise (and for any time on another date) the cell carries a short date. The attempt page shows date and `HH:MM`. The "Time left" countdown keeps `MM:SS`. The CSV keeps RFC 3339 with seconds. Since the UI revamp (2026-11-20) the page column is the window up to 1280 px (see "The page column"); the short times stay.
- **Name filter** (2026-11-16). A plain GET field `name`, a case-insensitive substring match applied in the handler after the list is loaded; sort links keep it. The CSV always holds every attempt, so an export never silently misses students.
- **Teacher rename** (2026-11-16). `POST /admin/exams/{id}/attempts/{aid}/rename` behind the admin session and CSRF token, for an attempt in any status, with the same name rule as a student's start. The name is overwritten with no history and nothing else in the attempt changes; students have no rename route, so a typo is fixed by the teacher, not by a second attempt.
- **Google sign-in** (2026-11-16, replaces the shared admin password). Authorization-code flow with `state`, `nonce` and PKCE `S256`, kept in one 10-minute `SameSite=Lax` cookie on `/admin/auth` that every callback expires. `go-oidc` verifies the ID token's signature against the provider's keys, issuer, audience and expiry; the app adds exactly one audience, the nonce and `email_verified`. Discovery is lazy and failures are not cached, so a server that cannot reach Google at boot still serves students. Logs carry fixed reason words only, never an email, code, state or token.
- **Allow-list and roles** (2026-11-16). A teacher is identified by the normalized email (trimmed, lower case); signing in needs a verified email and a `teacher` row with `allowed = 1`. Removal is a flag, because exams keep pointing at the row. Admins are exactly `GOEXAM_ADMIN_EMAILS`, put on the list at startup; the role is computed on every request and never stored, so the variable alone decides it.
- **Teacher sessions** (2026-11-16). One `admin_session` row per sign-in, owned by a teacher, for 12 hours. Sessions survive restarts and end by sign-out or by removal (rows deleted, and the session query joins on `allowed`). The old ownerless sessions were cleared at every start anyway, so migration 0003 drops them.
- **Exam ownership in one place per layer** (2026-11-16). `exam.Service` methods take an `Actor` and apply one condition (admin, or `owner_id` is the actor); anything else is `ErrNotFound`, so another teacher's exam answers 404 on every route. Results handlers resolve the exam through that check before touching attempts, which stay scoped by exam id. Migration 0004 adds a nullable `exam.owner_id` (SQLite refuses a `REFERENCES` column with a non-NULL default) plus triggers that refuse a NULL owner on insert or update; at every start the ownerless exams go to the first `GOEXAM_ADMIN_EMAILS` entry, which touches only NULL owners and so moves nothing later.
- **Exam codes and several open exams** (2026-11-16, replaces the one-open-exam rule). The code is 6 symbols of the resume-code alphabet from the shared `internal/shortcode`, drawn from the same random source as resume codes (`crypto/rand` in production). It is generated in the import transaction with up to 5 tries, the unique index is the backstop, and Replace keeps it. It is shown without a dash, so it cannot be taken for a resume code (`ABCD-EFGH`). Migration 0005 drops `exam_one_open` and adds `exam.code` with its check, the unique index `exam_code`, and the triggers `exam_code_required_insert` and `exam_code_fixed`; the column is nullable only for older exams, which get a code at the next start, a step that touches only exams without one. `Open` is one statement, the mirror of `Close`, and never closes another exam; `ErrOtherTeacherOpen` and its 409 are gone, and ownership is unchanged. `POST /start` takes `code` and `name`: the name is checked first, then the exam is looked up by code and open state inside the start transaction, so start and close stay serial. Unknown, closed and mistyped codes get one sentence, "No open exam has that code. Check it with your teacher." (422 on the form, 200 on `GET /?code=`). The plain landing page shows no title and does not say whether any exam is open; a title appears only through a link whose code names an open exam. Teachers see the code large on the exam page, the student link built from `GOEXAM_PUBLIC_URL` (`/?code=` plus the code), and a Code column in the exams list.
- **Fake OpenID provider** (2026-11-16). `internal/oidcfake` and `cmd/oidcfake` give tests, the load test and the browser scripts a real provider (discovery, keys, PKCE and client-secret checks). It is no bypass: the app has no test switch, the only way to reach the fake is `GOEXAM_OIDC_ISSUER`, which must be `https` or loopback, `cmd/go-exam` does not link it (a test checks), the image builds only `./cmd/go-exam`, and `cmd/oidcfake` listens on loopback only.
- **Exam length and schedule** (2026-11-16). Migration 0006 adds `exam.duration_minutes` (`NOT NULL DEFAULT 60`, checked 5 to 240, so existing exams keep 60), and nullable `opens_at` and `closes_at` (unix ms) with two checks: the open time is before the close time when both are set, and `is_open` is 0 whenever a time is set. The trigger `exam_duration_frozen` refuses a length change once an attempt exists, next to `Replace`'s `ErrFrozen` check. An exam is in one of three states: opened by the button, closed by the button, or scheduled (`is_open = 0` plus at least one time). Under a schedule `is_open` stays 0 because the checks then make the contradictory "button open and scheduled" state unstorable, and an older binary sees a scheduled exam as closed instead of open. `exam.AvailabilityAt(buttonOpen, schedule, now)` is the one rule for "can students start now" (closed, not yet open, open now), with the window `[open, close)`; the landing page, the start transaction (with its own time) and the teacher lists all go through it. `exam.LoadEntry` returns nothing for a closed exam, so no caller can show one; an unknown code and a closed exam are the same. Open and Close clear the schedule in the same statement, and saving a schedule sets `is_open = 0`. A not-yet-open code shows the title and "This exam opens at 08:00." (with the date when it is not today in `GOEXAM_TIME_ZONE`): 200 for the student link, 422 for Start, like every refused start. The web clock `Deps.Now` is used only to decide "today" in that message.
- **The live rows stay the scoring source** (2026-11-17, revisions). `question` and `question_option` keep their shape and meaning, and answers, scoring, shuffle and flags still read them by exam id. Answers point at these row ids, and the previous binary reads them, so no scoring path changes; only the attempt page reads the revision number.
- **A revision is one immutable row** (2026-11-17). Migration 0007 adds `exam_revision`: number, time, teacher, summary, the content settings as columns (`title`, `shuffle`, `show_result`, `monitor`, `duration_minutes`, `media_key`) and the questions as one JSON document in `content` (`dir`, `images`, and per question and option the source text, the HTML rendered at the time and the correct flag). The view shows the stored HTML, so a revision looks as it did even if the renderer changes. One row per revision makes append-only two triggers; normalised child tables were rejected because a child row could be added to an old revision later.
- **The schema enforces revisions** (2026-11-17). `exam_revision_no_update` and `exam_revision_no_delete` make revisions append-only; `exam_revision_in_sequence` and the primary key `(exam_id, number)` number them 1, 2, 3 per exam; `exam_revision_frozen` refuses a new revision once the exam has an attempt; `exam_content_matches_revision` keeps the exam's title, shuffle, result shown, monitor, length and media key equal to its latest revision. `exam_revision_frozen` lets revision 1 through, because existing exams with attempts (the olympiad has 51) get their first revision at the upgrade. The question, option and duration freeze triggers stay.
- **The schema, not `Start`, assigns `attempt.revision`** (2026-11-17). `attempt.revision` is a nullable integer; `attempt_revision_assign` fills it after insert with the exam's highest revision, `attempt_revision_current` refuses any other value at insert and `attempt_revision_fixed` refuses a change once set. The previous binary inserts attempts without the column, and with the trigger its attempts get a revision too. `attempt.Service.Start` is unchanged.
- **One writer of revisions** (2026-11-17). `insertRevision` is the only function that writes `exam_revision`. Import, Replace, Copy and the backfill call it in the transaction that writes the live rows, the revision first and then the `exam` row update, which `exam_content_matches_revision` requires. A future editor save must use it too.
- **Existing exams get revision 1 at startup** (2026-11-17). The source text has to be rebuilt from the stored HTML, which needs Go, so `BackfillRevisions` runs at every start after the exam codes step, like the owner and code steps. It touches only exams without a revision, stores revision 1 `Imported` dated at the exam's import by its owner, and puts the exam's attempts on it.
- **Rebuild is proven per exam, or the exam is skipped** (2026-11-17). `examfile.Rebuild` turns stored HTML into source text, then formats and parses the result again: every title, setting, question, option, correct flag and HTML string must come back identical. If any block fails, the exam gets no revision: it works as before, its attempts keep `revision` NULL, the exam page says so, History is empty, Download and Copy answer 409, and an error log line names the exam id and question position at every start. No inexact revision is stored, so a later release with a wider rebuild can still convert it. `cmd/rebuildcheck` runs the same rebuild on a database copy before deploy.
- **Images per revision** (2026-11-17). Each revision records its own `media_key`; `exam.media_key` stays unique and equals the latest revision's. Replace no longer deletes the previous folder, a copy gets a fresh key with its own copies of the files, and nothing deletes a revision's folder.
- **Download is the current revision in a canonical layout** (2026-11-17). `examfile.Format` writes the title, all four settings lines, questions numbered `1.`, `2.`, … and the correct option marked ` *`, keeping each block's source text. With images it is a zip of `<dir>/exam.md` plus each image at its recorded path. New imports keep the teacher's original image paths; upgraded exams never stored them, so their images are named by content hash. The file name is `exam-<CODE>.md` or `.zip`, built only from the code alphabet. A frozen exam can still be downloaded.
- **Copy is an import of the current revision as the copier** (2026-11-17). The stored revision becomes an upload in memory and goes through the same parse, image write and insert as an import, with a new media folder and a new code, closed, owned by whoever pressed Copy; its revision 1 reads `Copied from <title> (<code>), revision <N>`. A copy is correct exactly when a download re-imports correctly.
- **Rollback to the previous release** (2026-11-17). Student pages, the sweep, Open, Close, schedules, results, CSV, rename and delete keep working on an upgraded file, and its new attempts get a revision from the trigger. Its Import works, and the exam gets revision 1 at the next start of this release. Its Replace is refused by `exam_content_matches_revision` for an exam that has a revision; nothing changes and no image is deleted.
- **One save path for the editor** (2026-11-17). Every editor save builds the whole next exam and stores it through `replaceContent`, the function Replace uses: scope and freeze check, stale check, `insertRevision`, then the live rows replaced whole, in one transaction. No question row is updated in place, so the live rows and the latest revision cannot drift apart.
- **The editor validates by formatting and parsing** (2026-11-17). `parseEdited` formats the typed exam as a file and parses it with the importer; a parse error is the refusal. A typed question or option that starts with a code fence (the scanner's own `examfile.IsFence`) is first put on a continuation line, the only place the file format reads a fence. Then it checks that the parsed exam has the typed shape (title, question and option counts, correct flags, and every block's text apart from white space, so no text moved into another block), and proves the save by reading back its own download: the canonical file (zipped with its images when it has any) goes through the size limit, the upload reader and the parser again and must give the same title, settings, sources, HTML and correct flags. There is no second rule set; the cost is two parses per save and, with images, one zip per save. Every stored revision is by construction what importing its own download gives.
- **Outdated forms are refused** (2026-11-17). Every editor form posts the revision it was opened on. A different current revision is `ErrStale`, checked before any work and again inside the transaction next to the freeze check; the page answers 409 with the typed text and "This exam changed since you opened this page. Nothing was saved."
- **Editor images join the exam's media folder** (2026-11-17). An uploaded image is checked by content sniffing (`examfile.ImageName`, the import's check) and the 5 MB entry limit, named by content hash and written into the current revision's folder after validation, only when the folder does not hold that name yet. A save whose appended image line is not read as an image (for example after raw HTML) is refused before any file is written. The media key does not change. If the transaction fails, exactly the files this save created are removed. Image saves hold `Service.imageSaves`, one mutex from the folder check to the end of cleanup, so a refused save can never remove a file another save's revision uses. Saving appends `![](<name>)` as a new last line of the question text.
- **Summaries are written by the app** (2026-11-17): `Created in the editor`, `Question N edited`, `Question N added`, `Question N removed`, `Question N moved to M`, `Settings changed: ` with the changed names in the order title, shuffle, result shown, monitor, length. A question save adds `; correct option changed` when the stored text of the correct option differs from before, so moving the mark or rewriting the correct option counts, and reordering does not. They are still written and stored in English whatever the teacher's language; since 2026-11-21 History shows them in the page's language (see "Revision summaries in the page's language").
- **A new exam needs its first question** (2026-11-17). The new-exam form takes the settings and question 1 (with an optional image); the exam is created closed with revision 1 `Created in the editor` and opens on its editor page.
- **A save that changes nothing makes no revision** (2026-11-17). When the validated result has the same title, settings, sources and correct flags as the current revision, nothing is stored and the page answers as for a saved change.
- **Options are edited without scripts** (2026-11-17). Add, Remove, Up and Down are submit buttons with `name=do` that re-render the form with the changed option list and store nothing; only `do=save` saves. A visually hidden `do=save` button is the first submit button of each such form, so Enter in a text field saves. The option buttons carry `formnovalidate`.
- **No migration for the editor** (2026-11-17). The schema and the JSON of a revision are unchanged, so the previous release (`9da64ff`) reads edited exams like replaced ones: student pages, results, History, Download and Copy work, its editor routes answer 404 (rehearsed with `e2e/editor.py --rollback` on a copy of an edited data directory).
- **Archive is stored state, not a second open rule** (2026-11-18). Migration 0008 adds `exam.archived_at` (unix ms, NULL = not archived; existing exams NULL). `Archive` is one statement that closes the exam, removes the schedule and sets the date; `AvailabilityAt`, `LoadEntry` and `Start` are unchanged, so an archived exam is refused exactly like a closed one and a running attempt keeps its deadline.
- **The schema makes "archived and open" unstorable** (2026-11-18). The check `archived_at IS NULL OR (is_open = 0 AND opens_at IS NULL AND closes_at IS NULL)` sits next to the service refusal: `Open` and `SetSchedule` check scope, then archive state, inside their write transaction (`ErrArchived`, 409 on the page). Scope comes first, so another teacher's archived exam is still 404; the schedule rules come after.
- **Archive and Unarchive are idempotent presses on the exam page** (2026-11-18). Archive asks on a confirmation page (2026-11-19); Unarchive is one press; a second Archive keeps the first date; Unarchive returns the exam closed without a schedule; both land on the exam page so the opposite button is at hand.
- **"Show archived" is a view choice** (2026-11-18). `Service.List` returns every exam in scope with `ArchivedAt`; the handler leaves archived exams out unless the URL carries `?archived=1`, and counts the hidden ones for the link and for "All exams are archived." Archive is per exam, not per viewer.
- **Everything else keeps working on an archived exam** (2026-11-18): results, attempt pages, CSV, rename, delete, History, Download, Copy (the copy is not archived), and Replace and the editor while it has no attempts.
- **Rollback to `5716eb8`** (2026-11-18). Student pages, results, the editor, Close, Import and Copy work on an upgraded file; archived exams are listed as closed; rehearsed with `e2e/archive.py --rollback`.
- **A section is a property of its first question** (2026-11-18). Migration 0009 adds `question.section_title` and `question.section_html`, both NULL unless the question starts a section; the check keeps them paired and the title non-empty. A section therefore cannot be empty, is replaced with the questions in `replaceContent`'s transaction and is frozen by the 0001 question triggers. The previous binary writes question rows without these columns, so whatever it saves is consistently without sections, in the rows and in its revision.
- **`##` at column 0 starts a section** (2026-11-18), outside a fenced block: `##` alone or followed by a space or tab; `###`, `##x` and an indented `## x` stay text. The lines up to the next question number or heading are the section's instructions, where a `- ` or `shuffle:` line is text; settings go before the first heading. `Format` indents a `##` line inside question, option or instruction text, as it does a question number (`blockPad`).
- **Revisions gain `sections`** (2026-11-18): `title`, `source`, `html`, `start` per section, left out for an exam without sections; nothing is renamed, so the previous binary reads every revision.
- **One shuffle run per section** (2026-11-18). `layout` shuffles each run of questions from one section start to the next on its own, in file order, with the one seeded source; options follow as before. An exam without sections is one run, so every earlier attempt keeps its order (`TestLayout_Golden`, `TestLayout_UnsectionedOrderUnchanged`, the page goldens of `TestUnsectionedPages_Unchanged`).
- **Section scores are grouped totals** (2026-11-18). The right answers that make the total are counted per section, a question belonging to the last section that starts at or before it (since fill-in by the one Go score rule below, at first by a shared SQL fragment); nothing is stored, and they always add up to the total. The results list shows `S / T` per section after Score, the CSV the count after `total`; the student's score page shows the total only.
- **The editor moves boundaries, not numbers** (2026-11-18). Start, Edit and Remove section and a move across a boundary change `Sections` on the typed exam and save through the one editor path; a question that crosses keeps its number and joins the neighbour's section. The parser is the only place that refuses an empty section; `editorError` words it for the form.
- **Section summaries** (2026-11-18): `Section K started at question N`, `Section K edited`, `Section K removed`, `Question N moved to section K`; sections are named by position, as questions by number.
- **Rollback to `293ab19`** (2026-11-18). It never reads or writes the section columns and ignores `sections` in a revision, so exams without sections work as before and `user_version` 9 does not stop it. A sectioned exam shows no headings there, shuffles all its questions as one run, has total-only results, and an attempt in progress gets another order (answers and scores are keyed by question). Its editor save or Replace on a sectioned exam without attempts stores it without sections (rows and new revision agree; earlier revisions keep them); its Download and Copy leave them out. Rehearsed with `e2e/sections.py --rollback`.
- **A question is fill-in when it has accepted answers** (2026-11-18). No kind is stored. Migration 0010 adds `question.accepted_answers`, a JSON array of 1 to 10 strings, NULL for a multiple-choice question; the 0001 question triggers freeze it, and it is replaced with the rows in `replaceContent`'s transaction. Revisions gain `answers` per question, left out for a multiple-choice question; nothing is renamed, so the previous binary reads every revision.
- **`=` lines list accepted answers** (2026-11-18). A line `= ` plus plain text, indented by fewer than 8 columns (a tab counts 4), outside a fenced block and outside section instructions, is an accepted answer of the current question: one line, 1 to 200 characters, 1 to 10 per question. A question with both options and accepted answers, or with neither, is refused. Why 8: `Format` keeps a stored text line that starts with `=` as text by indenting its block 8 spaces (`blockPad`), while one tab or alignment under `100.` still gives an answer.

The CSV follows the language of its own request, which carries the cookie of the page the link was on: the header row and the three status words come from `csv.*` keys; section titles, names, numbers, RFC 3339 times, column order, quoting and the file name do not change, and `attempts.csv.golden` is byte-identical (`TestCSV_Language`).
- **Scripts hold no word** (2026-11-21). `entry.js`, `results.js` and `copy.js` already read their words from `data-*` attributes; those values are now `t` calls. `exam.js` reads every word from `<div id="exam-text" hidden data-…>` in the `scripts` block of `exam.html`, outside `<main>`, so the golden pages keep their `<main>`. A text with numbers is rendered with the placeholders `{done}`, `{total}` and `{n}`, which the script fills. `TestScripts_HoldNoWords` refuses a string of words in a script.
- **The switch on the exam page** (2026-11-21). `exam.js` takes the press, sends what is unsent and waits until no answer is unsaved or in flight, at most 5 s; then it sets `leaving`, so no unload prompt appears, and submits the switch's form. If saving does not finish in time, nothing navigates and the save line already says why. The monitor is unchanged and gets no exemption: an event needs the page hidden or unfocused for more than 3 s, and a switch keeps the page visible and focused until the new page is there. A signal from the page asking the monitor to ignore an absence was not added, because any client could send it to hide a real one. `e2e/language.py` proves it with the monitor on: every answer saved, no flag.
- **Goldens untouched** (2026-11-21). The seven files of `internal/web/testdata/unsectioned/` stayed byte-identical through this unit and `TestUnsectionedPages_Unchanged` was not edited, which is stricter than a re-baseline. English held because its text was cut from the templates and the Go source into the `en` maps, never retyped; during the work an English dump of every page state was compared before and after each step, and afterwards `TestPages_SameSkeleton` holds both languages to the same markup apart from the text.
- **Indonesian wording** (2026-11-21). Plain, friendly standard Indonesian, neither stiff officialese nor chat register; student pages are written for fifth graders. Student pages say `kamu`, teacher and sign-in pages `Anda`, never both on one page. One glossary holds the terms (`ujian`, `kode ujian`, `kode lanjut`, `soal`, `nilai`, `bagian`, `isian`), and refusals keep their meaning: the Indonesian of "No open exam has that code" does not confirm that a code exists either. The user reviewed the whole Indonesian text table (`TestMessages_ReviewTable` prints it), and the wording picks of that review are in; the user then reviewed the Indonesian screenshots of `e2e/walkthrough_id.py`. The exam bar's retry state "✗ Belum tersimpan — mencoba lagi" was shortened to "✗ Belum tersimpan…" so the bar stays on one line at 360 px.

## Rejected alternatives

- A stored score column or stored shuffle order: both create stale-copy bugs.
- Resume by name: anyone could open a classmate's attempt.
- A test-only switch for a shorter exam duration or insecure cookies: tests inject time instead.
- A backdoor password next to Google sign-in: a second way in that every attacker would try first. Recovery is an environment change plus a restart.
- Storing the sign-in state in a table: anyone could write rows without signing in.
- Provider discovery at startup: an unreachable provider would stop the server, and with it the students.
- Relaxing the session cookie to `SameSite=Lax` so the callback could redirect: it would weaken CSRF protection for every teacher request to fix one landing page.
- Telling a student that a code's exam is closed: it would confirm that the code exists.
- A dash in the exam code: it would look like a resume code.
- A stored "open now" flag flipped by the sweeper at the schedule times: derived state that could go stale; the times and `AvailabilityAt` decide on every request.
- A test switch or a settable clock in the running binary to check schedules in the browser: a second way to change behaviour in production. The browser run waits on the real clock instead.
- Ending attempts at the close time: it would break the rule that closing stops new starts only and a started student keeps their own deadline.
- Removing a schedule by saving an empty form: two ways to do one thing, and unclear whether the exam should end open or closed. Open and Close remove it and say which.
- Revision-scoped `question` rows: every scoring query and the previous binary would read all revisions' questions.
- Rebuilding the source text in the SQL migration: it needs Go.
- Storing an inexact revision with a flag: append-only would keep it wrong for good.
- Copying by rewriting media keys inside stored HTML: a second render path.
- A new dependency for HTML parsing in the rebuild: the input is the app's own renderer output, and every result is proven by parsing it again.
- Last save wins between two teachers or two tabs: a silently lost edit. An outdated page is refused instead.
- An empty exam without questions: every stored revision must be an importable file.
- A separate validator for form input: a second rule set that could drift from the importer.
- A new media folder per editor save: it would copy every image on every save.
- Updating single question rows: a second writer next to `replaceContent`, and the live rows could drift from the revision.
- A summary typed by the teacher: the app knows what changed.
- Keeping an uploaded file across a refused save: it needs server-side drafts; the form says to choose the file again.
- An `archived` argument to `AvailabilityAt` or a condition in `LoadEntry`: a second open rule.
- A trigger instead of the archive check: the check also refuses archiving without closing, and matches 0006.
- An archived flag plus a separate date column: two values to keep in step.
- Restoring the old schedule on Unarchive: a stale schedule could open the exam by itself.
- A filter argument on `Service.List`: the page needs both the shown rows and the hidden count.
- Archive buttons in the rows of the exams list.
- Telling a student that an exam is archived: it would confirm that the code exists.
- An `exam_section` table: a second set of freeze triggers, and rows the previous binary's Replace would leave behind.
- A stored section number per question or stored section scores: derived values.
- Nesting questions under sections in the revision JSON: it renames `questions` for every reader.
- A seed or shuffle setting per section.
- Refusing `- ` lines in section instructions: everything up to the next question number is instructions.
- A hand-written "a section keeps a question" check next to the parser's: a second rule that could drift.
- Section support in the rebuild of older exams: they cannot have sections.
- A nullable `answer.option_id` with a text column: a rebuild of a live table, and `1bddec5` reads `option_id` as a number and would answer 500 on the exam and attempt pages.
- An `accepted_answer` table: a second set of freeze triggers, as with `exam_section`.
- A `question.kind` column: derived from the accepted answers.
- A separate override table: an override lives exactly as long as its typed answer.
- A stored mark, normalized text or score: derived values.
- Scoring in SQL through a Go function registered in the SQLite driver: a second copy of the rule, unusable from `sqlite3`, and a process-wide registration.
- A backslash escape for `=` lines: it would change the stored source of older revisions.
- A 4-column indentation limit for `=` lines: a tab, or alignment under `10.`, would stop being an answer.
- A number keyboard, `inputmode` or `type=number` on the answer box: a comma must always be typeable.
- Refusing duplicate accepted answers.
- Reading the former setting names next to the new ones for a while.
- Renaming the database file at startup.
- Script dialogs for confirmations: two paths to keep equal, one with and one without scripts.
- A theme switch: it needs a stored choice or a cookie.
- Keeping Pico and overriding it: more override rules than an owned base, and colours outside the contrast test.
- An import page of its own: the projector and confirmation pages are the only new routes.
- Column labels written by CSS `content` on phones: the words would live in the stylesheet, outside the template.
- A JSON endpoint or push for the results list: a second rendering path or a held connection; the refresh fetches the page itself.
- A PNG or ICO favicon: the SVG mark is enough for the browsers in use.
- A return-URL field for Open and Close: an open redirect to guard for ever. The `Referer` header: not always sent.
- A serif "paper" type for student pages (the first revamp look): replaced by the "Friendly classroom" direction and one legible sans font.
- Web fonts from a third party: a request to another site from every student page, and a wider policy header.
- An unversioned font URL, or a conditional request per page: either a stale font for a year or a request on every load; the versioned URL is cached for good.
- The font's `@font-face` in an inline style: the policy forbids inline styles.
- Inline SVG icons or a sprite: markup on every pinned button and link. `<img>` icons: markup too, and an alternative text to keep beside the word.
- Counting attempts with `List` on every exam page load: it loads and scores every answer. A stored attempt counter: derived state that can go stale.
- A body class per audience to switch fonts: the font follows the elements that hold student text instead.
- Six boxes, one per code symbol, and a `•` mask: the user chose one box with a `_` mask (mockup C of the entry round).
- Tabs through `:target` (a fragment in the address and a jump) or through `:has()` (not in every browser in use); keeping the `<details>` fold for Resume.
- `maxlength` 6 and 9: they cut a code typed or pasted with separators before the server can strip them.
- Rewriting the value on every keystroke, also during a composition: letters repeat or vanish on Android keyboards.
- The alphabet or the hint sentences written into the script: a second copy of `shortcode.Alphabet` and words outside the template.
- A picture of the product on `/`.
- A link (GET) that switches the language: a prefetch or an `<img>` on another site could set the cookie.
- The `Referer` header as the switch's return path: not always sent, and it can name another site.
- English text as the catalogue key: an English fix would change the key of every translation.
- An embedded JSON catalogue or a new i18n dependency: a file to load and a library to keep for what Go maps and a few tests do.
- A language stored on the server or per teacher: stored state for what one cookie does, and students have no account.
- A `?lang=` parameter: a shared link would carry the sender's language, and every link and form would have to pass it on.
- A signal from the exam page telling the monitor to ignore the absence of a switch: any client could send it to hide a real absence, and the 3 s rule already decides the case.
- Translating revision summaries when they are written: the stored text would depend on who saved, and old summaries would stay English anyway.
- Re-baselining the page goldens for the languages: English kept its bytes, so the goldens stay a regression check.
- The switch at the foot of every page (the plan's first default): the user chose the top right, so that a student whose phone is set to English finds the switch at once.

## Traps

- With one connection, calling `s.db` or another service method inside an open transaction deadlocks. Scan and close rows before the next statement.
- Go's cookie jar will not send `Secure` cookies over plain HTTP. Test and load clients set the `Cookie` header by hand. Browsers do send them on `http://localhost`.
- Chromium logs non-2xx page loads as console errors that page code cannot suppress. The e2e scripts exempt exactly the 422 of a reused resume code (`exam_flow.py`), the 422 of a refused exam code (`exam_codes.py`), the two 422s of an early and a refused start (`scheduled_exams.py`), the 422 and two 409 page loads of `editor.py` (a refused save, an outdated page, the editor of a frozen exam), in `archive.py` the two 409 page loads of Open and Save schedule from pages opened before the archive plus the 422 of a refused start (with `--rollback`: two 500 page loads and one 422), in `sections.py` the 422 of an empty section title and the 409 of an outdated section form (none with `--rollback`), in `fillin.py` the 422 of an empty accepted answer (with `--rollback`: the 422 of the refused editor save and the 500 of Copy; none with `--returned`), in `screenshots.py` the 404 of its missing-page picture and the 422 of its refused resume code, and in `walkthrough.py` the 422 of each refused resume code, once per load. `fillin.py` also ignores `net::ERR_INTERNET_DISCONNECTED`, as `student_ui.py` does, because it goes offline on purpose. `GET /?code=` answers 200 also for a code that names no open exam, and for an exam that is not open yet.
- `scheduled_exams.py` needs the server's time zone (`--time-zone` equal to `ANSWERBOX_TIME_ZONE`) and waits on the real clock, about two minutes.
- An exam row cannot be inserted without a code, and a set code cannot change. Tests that insert exam rows by hand give each a distinct valid code.
- `shortcode.Random` reads 2n bytes per round; tests with scripted random readers rely on it.
- The session cookie is `SameSite=Strict`, and a browser withholds it on a redirect chain that started on another site. The sign-in callback therefore answers 200 with a meta refresh and never redirects into `/admin`. The browser scripts run the fake provider on `127.0.0.1` and the app on `localhost`, so the callback crosses sites as it does with Google, and they refuse equal hostnames.
- The sign-in button is a link to `/admin/auth/start`, not a form: under `form-action 'self'` Chromium blocks a form submission that redirects to the provider.
- An OpenID request (discovery, keys, token exchange) must never run inside an open database transaction: with one connection, a slow provider would stall every request.
- A binary older than migration 0006 refuses to open a scheduled exam (the `is_open` check fails, the page answers 500), and its Close leaves the times in place, so the schedule returns with the new binary. Before rolling back past 0006, press Open or Close on every scheduled exam, or clear `opens_at` and `closes_at` with SQL.
- `exam_content_matches_revision` refuses an `exam` update whose content columns differ from the latest revision: insert the revision before updating the exam row. A test that updates `exam.title` by hand on an imported exam is refused.
- Rolling back to the previous release: Replace is refused for every exam that has a revision (nothing changes); an exam imported during the rollback gets revision 1 at the next start of this release.
- `rebuildcheck` needs a copy without a `-wal` file (take it with `sqlite3 ".backup"`); it opens with `mode=ro&immutable=1` because `mode=ro` alone cannot read a WAL-mode copy in a read-only place.
- `e2e/revisions.py`, `e2e/editor.py`, `e2e/archive.py`, `e2e/sections.py`, `e2e/fillin.py`, `e2e/walkthrough.py` and `e2e/screenshots.py` need a fresh instance, like the other scripts.
- The editor path must never `RemoveAll` an exam's media folder: older revisions share it. Remove only the files the failed save created.
- Every `<textarea>` in the editor templates starts with a line break after the opening tag; the HTML parser drops one leading newline, so a text that starts with a blank line would otherwise lose it.
- The hidden save button must stay the first submit button in each question form (the browser's default button for Enter), and every option button needs `formnovalidate` so a required field cannot block it. `.visually-hidden` also clears the button's minimum height, padding and border, or the hidden button takes room on a phone.
- A new file rule needs a code in `examfile`'s English table and an Indonesian entry in `messages_file.go`; `TestMessages_FileCodes` fails until both exist. `editorError` maps by code, not by wording.
- The previous release (`5716eb8`) shows an archived exam as closed with Open and the schedule form; either press answers its 500 page and changes nothing. Unarchive in this release before rolling back, or run `UPDATE exam SET archived_at = NULL WHERE id = ?`.
- A hand-written test row cannot be archived while open or scheduled: close it in the same `UPDATE`.
- Web tests match the row tag `<tr data-exam-id="N">` exactly: mark archived rows with the badge, not an attribute.
- An exam opened by the button shows no Open form, so a browser check that presses Open after the archive loads that page while the exam is still closed.
- The check of migration 0009 spells out `section_title IS NOT NULL`: without it a NULL title makes the check NULL, which SQLite accepts.
- A new template action goes on the line of the tag that follows it, never on a line of its own, or the pages of an exam without sections change and the page goldens fail. The fill-in branch of a template opens on the line of the tag it replaces (`{{if .FillIn}}…{{else}}<existing tag>`) and closes on its closing tag, for the same reason.
- The goldens of `TestUnsectionedPages_Unchanged` were re-baselined once, at the UI revamp head (2026-11-20), after the check that their facts agree with the `293ab19` goldens; `attempts.csv.golden` is still `293ab19` output. They are never regenerated again, also not for a later feature, and the test has no flag to do it; a diff there is a regression, not a new golden. A change to the `<main>` markup of the student exam, student result, exam, revision, results or attempt page fails it.
- On those golden pages the texts with `✓` and `✗` (`.review-mark`, `.correct-mark`, `.option-marks`, `.auto-mark`), the `.eyebrow` texts, `.counts` and table cells are compared character for character: an icon goes on through CSS, never in front of them in the markup.
- Text moved into `t` keeps its bytes on those pages only because `t` escapes for itself (`&`, `<`, `>`) and returns `template.HTML`. Do not change `t` to return a plain string: `html/template` would then write `'`, `"` and `+` as entities and the goldens would fail.
- `rebuildStored` must not read the section columns or `accepted_answers`: `cmd/rebuildcheck` opens copies at schema 6 to 9.
- Rolling back to `293ab19` with sectioned exams: they lose their headings and per-section shuffle there, and its editor save or Replace drops their sections. First list them (`SELECT DISTINCT e.code FROM exam e JOIN question q ON q.exam_id = e.id WHERE q.section_title IS NOT NULL`), close each one, let its running attempts end, and do not edit, replace, copy or download them until this release is back. There is no SQL shortcut: clearing the columns would leave the latest revision saying otherwise, and the freeze refuses it once attempts exist.
- Rolling back to `1bddec5` with fill-in exams: they cannot be answered there and their scores read too low. First list them (`SELECT DISTINCT e.code FROM exam e JOIN question q ON q.exam_id = e.id WHERE q.accepted_answers IS NOT NULL`), close each one and let its running attempts end. Until this release is back, do not read their results, download, copy or replace them, and do not delete their attempts (its delete also removes the typed answers).
- With one connection, `loadAnswers` reads and closes the picks before it queries the typed answers (the first trap above); keep one result open at a time.
- The answer box needs `user-select: text` under the monitor's `user-select: none`, or a student cannot place the cursor or select inside it.
- A temporary image name starts with a dot and ends in `.tmp-` plus a random suffix, so it never matches the media handler's name rule (32 hex characters and an image extension) and is never served or referenced. A new name scheme for images or temporary files must keep the two apart. A file left by a killed write stays in the folder until removed by hand. The backfill's `readImages` takes every file of a folder as an image, but it reads only folders of exams without a revision, and no write of this release goes there; a change that lets it read other folders must skip dot names.
- A data directory or env file from before the rename stops the start (see the 2026-11-19 entries): rename all three database files together while the app is stopped, never the main file alone.
- Each page has at most one `[role=alert]`, and the exam page one `.zone-note`, because the browser scripts select them without an index.
- The 992 px breakpoint is shared by `app.css` and `exam.js` (`matchMedia("(max-width: 991.98px)")`); change it in both. The exam bar's height is `--ge-bar` (64 px), and every offset of the exam page uses that token; `exam.js` measures the bar instead of knowing its height.
- A new colour state (a new text or control colour on a background) needs its pair in `TestCSS_TokensContrastAA`, in both themes.
- A `url("…")` in `app.css` must name an embedded file under `static/`, or `loadAssets` fails and the app does not start. Write such references with double quotes; the rewrite reads no other form.
- The font preload's `href` must come from the `static` function (`font_preload` in `brand.html`), so it equals the versioned URL in the served stylesheet and the font is fetched once; a font preload needs `crossorigin`, also on the same origin.
- The code boxes keep `maxlength="16"`: a lower limit cuts a code typed with separators before the server can strip them.
- `entry.js` cleans the value on `compositionend`, because Chromium sends no `input` event after it; a rewrite of the value during a composition repeats or swallows letters on Android keyboards.
- The tests pin the exact strings `<div class="entry">`, `class="landing-lead"` and `class="landing-hint"`; each state of `/` has one `autofocus`.
- Template text is always a key: `TestTemplates_NoLiteralText` refuses letters outside an action, apart from `<code>`, `<pre>` and a short allow-list.
- A text with markup has an `_html` key and goes through `th`; its English and Indonesian hold the same tags in the same order (`TestMessages_HTMLKeys`).
- A script gets a new word only through a `data-*` attribute filled by `t` (`TestScripts_HoldNoWords`).
- A page that a POST renders on a path without a GET page needs `returnPath` on its data, or the switch there sends the visitor back to the POST path.
- A new summary form needs a case in `exam.ParseSummary` and a `summary.` key, or Indonesian History shows it in English.
- A new page state belongs in `pages_fixture_test.go`: the language tests (`TestPages_SameSkeleton`, `TestIndonesianPages_NoEnglishLeft`, `TestCSV_Language`) see only the states listed there.
- Go's cookie jar withholds the `Secure` language cookie on plain HTTP, as it does the others: tests set `Cookie: answerbox_lang=id` by hand.
- The browser scripts run with Playwright's default `en-US` locale, which is why they read English; only `language.py` and `walkthrough_id.py` set another locale or press the switch.

## Open questions and known limits

- Option ids follow file order, so the page source reveals the original option order under `shuffle: questions, options`.
- `/start`, `/resume` and `GET /?code=` are not throttled. Guessing a resume code at 100 active attempts has odds of about 1.5e-10 per try. There are 30^6 = 729,000,000 exam codes, so one guess hits with odds of about 1.4e-9 per open exam. A hit gives what a student in the room has (the title, and after a start the questions without the key), and `GET /?code=` shows an open exam's title without starting, and the title and open time of a scheduled exam that is not open yet.
- Schedule times use the app's zone (`ANSWERBOX_TIME_ZONE`), not the student's device.
- The early page ("This exam opens at …") does not refresh by itself; the student presses Start again.
- A 5-minute exam starts in the warning colour of the countdown.
- In a zone with daylight saving, a schedule time in the skipped or repeated hour follows Go's rules (`time.ParseInLocation`, as `time.Date`).
- On some devices the countdown may stall while asleep and offline. The server still rejects late answers.
- The CSV follows the browser's current choice, so a results page left open before a switch in another tab downloads the CSV in the new language.
- A results list that refreshes itself after a switch in another tab mixes the two languages until the page is reloaded.
- A switch on a form shown again after a refusal returns to the form's GET page, and the typed text is lost.
- A stored summary in a form the app does not write is shown as stored, in English.
- Download file names, the plain-text 500 fallback, `/healthz` and log lines are English.
- `Accept-Language` with an underscore (`id_ID`) is not read as Indonesian.
- The language menu closes by pressing the icon again or a language; Escape and a press elsewhere leave it open (it has no script).
- The language proof is Chromium only.
- Monitor flags are evidence for a conversation, not proof: a notification shade, an incoming call, a rotated phone or a long-press on a phone (logged as "Right-clicked") also counts. On touch devices only width changes count as a resize, so sliding address bars raise no flags. Leaving the page and resizing name the first visible question, which can still be the previous one.
- Clock times on teacher pages have no seconds, so several flags in one minute show the same time; they are still listed in order.
- At the very top of the exam page, before the bar is stuck, the monitor banner briefly covers the first question's heading and the top of the navigator for its 5 s.
- A student name that is one unbroken word wider than about 220 px still makes the attempts table scroll sideways.
- Browser proof covers desktop Chromium and, for the monitor, Chrome on a real Android phone (2026-11-16). Safari is not tested; there is no Apple device to test on.
- With the monitor on, question and option text cannot be selected, so on Android a long-press opens neither a selection nor Chrome's search sheet (checked on a real phone, 2026-11-17); it is still flagged. With the monitor off, text selects as usual.
- An email taken out of `ANSWERBOX_ADMIN_EMAILS` stays an ordinary teacher until an admin removes it on the Teachers page.
- Removed teachers are not shown on the Teachers page; their exams stay on the admin's exams list with their email as owner.
- The allow-list is keyed by email, not by Google's account id, so a re-issued address would inherit access.
- A removed teacher's open exam stays open until an admin closes it.
- An exam code cannot be regenerated or chosen; if one leaks, the teacher closes the exam.
- "Never reused" holds because exams are never deleted; a delete feature would have to keep retired codes.
- Sign-in is proven in Chromium only; other browsers are covered by the live check.
- The rebuild of older exams covers paragraphs, line breaks, bold, italics, inline code, fenced blocks and images; an older exam with a list, link, quote, heading or raw HTML stays without a revision, and so does one with bold-and-italic text written as `**_x_**` or `__*x*__` (stored as `<strong><em>`) or a paragraph ending in a no-break space.
- Images of old revisions are never deleted, so `media/` grows with each Replace.
- A download of an exam uploaded close to 10 MB can come out slightly larger and then be refused on import.
- The current content is stored twice, in the live rows and in the latest revision; one writer and one trigger keep them equal.
- "Never reused" for codes still holds with copies: a copy draws a new code.
- Editor text is stored in the parser's form: trailing spaces and the common indentation of continuation lines are dropped, as in a file.
- A non-correct option ending in `*`, or a line holding only `-`, is refused with the parser's count message ("more than one correct option", "option N has no text"); the form's format note explains `\*` and `\-`.
- An exam whose download would pass 10 MB cannot be saved in the editor until an image reference is removed.
- A refused or re-rendered question form loses the chosen image file (a browser never refills a file input); the form says so.
- An editor request over 11 MiB answers the 413 page and the typed text is lost.
- Remove asks on a confirmation page; the removed question stays readable in the previous revision and cannot be restored from it.
- Images removed from every text stay on disk.
- A question or option that begins with a code block is stored with an empty first line; the form and the download show it.
- A question or option imported with a fence on its first line is refused with "code block is never closed" when its form is saved, until the fences are corrected.
- In the editor, a question or option whose first line starts with three backticks is read as opening a code block, so one-line inline code written there as ```` ```x``` ```` is refused with "code block is never closed"; write `` `x` ``. Narrowing the fence rule to CommonMark's (no backtick after the fence) would change how imported files are read.
- An upload whose bytes the exam already uses elsewhere is not refused when its new line is hidden: no stray file is left, and the line does not show.
- Unarchive does not bring a schedule back.
- The archived view lists every exam, not archived ones only.
- Only the date of the latest archive is kept, not who archived.
- A schedule POST with an unparsable time on an archived exam answers 422 instead of 409 (a browser cannot send one).
- After a section heading, a settings-like or option-like line is instruction text, and a question typed without its number right after a heading becomes instructions (the file is then usually refused for a section without questions or a wrong next number).
- Add question appends to the last section; the teacher moves it up from there, one step across each boundary.
- A section's only question cannot be moved or removed until its section is removed.
- Two sections may share a title, which gives two equal CSV headers.
- With several sections the results table scrolls sideways inside its wrapper.
- The attempt page shows the headings but no section scores, and the results list cannot be sorted by a section.
- An attempt in progress on a sectioned exam gets another question order if the binary is rolled back to `293ab19`.
- A file that imported before sections with a `##` line at column 0 inside question or option text is now refused on import ("the first section heading must come before question 1"); that includes a download taken from such an exam on the previous release. Stored exams are unaffected: pages use the stored HTML, and Format indents such lines.
- A file that imported before fill-in questions with a line starting with `=` inside question or option text, indented fewer than 8 columns, now has an accepted answer there on import: it is refused ("has both options and accepted answers") or changes meaning. Stored exams are unaffected: pages use the stored HTML, and Format indents such lines 8 spaces.
- An `=` line indented 8 columns or more is text, not an accepted answer.
- Matching uses simple case folding, so `ß` does not match `SS`; accents and punctuation count; `1.5` and `1.00` are not numbers in Indonesian notation and match as text only.
- Duplicate accepted answers are allowed.
- With the monitor on, copying or long-pressing inside the answer box is flagged like anywhere else on the page, and a text drop into it is blocked and flagged as a paste (a drop inserts text like one). The box is proven in Chromium only.
- The CSV has no typed answers, and the attempt page keeps no history of overrides, only the latest mark.
- A score read on `1bddec5` for a fill-in exam is too low: the fill-in questions count as wrong there.
- An exam page loaded before the UI revamp lands on the exams list after Open or Close, until it is reloaded.
- On a phone the exams list leaves out the Questions and Attempts counts, and the results list leaves out Started and Finished.
- While the list can change, a results page refreshes the whole list every 10 s per visible tab.
- Copy link needs `https` or `localhost` (the browser offers the clipboard only there); elsewhere the button stays hidden and the link is copied by hand.
- The favicon is SVG only.
- The look is proven in Chromium and on one Android phone (Chrome on a vivo, light and dark, both codes typed on `/` with its keyboard, 2026-11-20).
- The student font has no italic face; `<em>` in question text is slanted by the browser.
- A browser without CSS masks would show a filled square where an icon belongs; Chromium, the only engine proven, has masks.
- The tint of a picked option needs `:has()`; an older WebView shows the other three cues (filled bubble, check mark, bold text) without it.
- On a keyboard that composes, an upper-case letter, a refused character or the resume code's dash settles only when the word ends (a space, a tap elsewhere, Enter).
- Once `entry.js` has cleaned the text in the exam code or resume code box, Ctrl+Z does not undo inside that box.
- An error page offers "Teacher pages" only when the address as sent starts with `/admin/` (or is `/admin`). A hand-typed address that writes "admin" with an escaped letter, such as `/%61dmin/exams/999`, reaches the teacher pages but its error page shows only the start-page link; reading the decoded address instead would show the link on `/admin%2Fexams`, which is a public page.
- Without scripts a screen reader reads the code boxes' placeholders as underscores.
- In the dark scheme the open tab and the closed one differ by shape, the join to the card and the green bar, not by lightness (1.8 : 1).
- The alignment of the code mask with the typed text is proven in Chromium only.
